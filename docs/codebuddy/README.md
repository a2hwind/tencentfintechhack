# CodeBuddy / WorkBuddy proof of usage

The handbook requires that the project is built with CodeBuddy or WorkBuddy and that the submission carries at least three screenshots as proof — without them the project is not scored.

Keep the evidence here as it is produced, not reconstructed on the last night:

- `NN-<what>.png` — one screenshot per meaningful CodeBuddy session (a feature implemented, a test made green, a refactor, a bug found by the assistant). Name them in order.
- `sessions.md` — one line per screenshot: date, what was asked, what changed, which pull request or commit it landed in.

Rule from day one: every pull request carries a CodeBuddy screenshot or session log in this folder, so the mandatory proof assembles itself.

Written development-process note (for the project description, in `docs/submission.md`): say accurately which parts were built in CodeBuddy and which were not, with the screenshots above as evidence for the CodeBuddy parts. Name the case study at the start of the presentation: FinTech track, Aspire, The Internal Brain.
